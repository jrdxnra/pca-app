Main route

Different UI entry points feed the same engine: each + Fill entry arms a context-specific fill mode, then generates a draft from template and history.

Core idea

Template + Fill

The selected template defines the shape. Fill decides whether the app asks for a generated draft.

Step 1

Choose template

The selector offers plain templates and + Fill variants.

Step 2

Arm fill state

Either a + Fill selector value (structure-fill:...) or a planner toggle enables fill mode. Same engine, specialized path for that selection context.

Step 3

Send request

The app posts client, category, goals, and template id to the fill draft API.

Step 4

Server gates + loads

Auth, account access, Firebase Admin, and recent workout context are checked before drafting.

Step 5

Return result

The server returns a structure-aware draft or a fallback draft if the template cannot be resolved.

What your eye should follow

A

Selection

B

Generation

The app sends the draft request and the server tries to build a structure-aware workout from recent history.

C

Fallback

If the template is unavailable, the server does not guess a new structure. It falls back to a usable draft path.

Inputs that matter most

Input

Selected template

Controls the shape of the workout and whether structure sections can be built.

Input

Recent history

Used to rank movements, choose structure-aware content, and create the filled draft.

Gate

Auth and access

If auth, account lookup, or Firebase Admin access fails, the request stops before drafting.

Fallback

No usable template

Clones the latest usable workout or returns a minimal blank draft if there is no history.

Output

Saved workout

The final result is a draft response, with a source strategy telling you which path won.

Other things that can override the score

How notes are weighted There is no direct "notes %" weight. Notes feed keyword/context signals, so they mostly influence the 38% goal-intent bucket and can indirectly affect section matching.
Hard blocks Auth/account/env gates and blocked movements stop or filter candidates before scoring.
Penalties Avoid list, repeated movement reuse, and recent repetition can push otherwise good candidates down.
Fallback trigger If structure sections are unavailable or history is not usable, + Fill falls back to clone/minimal draft paths.

Next step: explicit + Fill flow rules

These rules align the generator with training intent: one-off sessions prioritize variety, while weekly/monthly/period planning prioritizes controlled repetition and progression anchors.

Single flow rule

High diversity bias

Prefer novelty inside the workout and reduce same-family repeats unless a movement is strongly supported by goals and profile fit.

Good for: one-off sessions where freshness matters more than long-block progression.

Weekly flow rule

Repeat key lifts when planned

Allow repeat for anchor movements or movement families when the plan demands continuity, but block or reduce repetition under pain/fatigue/poor-tolerance signals.

Good for: 3-6 workout sequencing where performance trend matters.

Monthly/period rule

Progression lanes

Keep anchor lifts consistent across the block, rotate accessories with intent, and use progression continuity as a stronger signal than short-term novelty.

Good for: block planning, skill carryover, and measurable progress over time.

One backend engine, multiple + Fill variants

"Multiple + Fill versions" means multiple entry flows and selection formats, not separate engines. The UI variant changes the context and inputs, then all routes converge on the same fill draft backend.

Single flow

Workout editor + Fill

Best for one workout at a time. Uses current workout context and defaults to single flow behavior.

Monthly flow

Month planner + Fill

Optimized for batch month creation. Sends monthly flow header and month/session goals context.

Weekly flow

Week assignment + Fill

Optimized for weekly sequences. Sends weekly flow header, sequence index, and avoid lists.

→

Shared Fill Draft Backend

All variants call the same backend route. The backend reads flow as single/monthly/weekly and tunes behavior with that context.

Same core scoring: goal, section fit, client profile, progression, history.
Flow-specific tuning: headers and payload shape (single vs monthly vs weekly).
Same fallback safety net: clone/minimal draft when required inputs are unavailable.
